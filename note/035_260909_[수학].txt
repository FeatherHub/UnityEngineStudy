template<class T, class U>
static constexpr T Lerp(const T& A, const T& B, const U& Alpha)
{
    return (T)(A + Alpha * (B - A));
}

Lerp(A, B, α) = A + (B − A)·α

(1 − α)·A + α·B로 풀어 쓰면 "A와 B를 α 비율로 섞는다"

---

target − start는 현재 위치에서 목표까지의 벡터이고, 
target 혼자는 월드 원점에서 목표까지의 벡터

start = 100, target = 50, Δt·speed = 0.1

Lerp는 100 + (50 − 100)·0.1 = 95라서 목표 쪽으로 가요
target 혼자는 100 + 50·0.1 = 105라서 목표에서 멀어져요

목표가 매 프레임 움직여도 알아서 쫓아가요

---

(target − pos)·speed, 즉 남은 거리에 비례하는 속도

---

속도가 남은 거리에 비례하니까 결과는 지수 감쇠

멀면 빠르고 가까울수록 느려지는 ease-out

---

함정

"속도 = (target − pos)·speed"의 정확한 해
pos(t) = target + (pos₀ − target)·exp(−speed·t)

프레임 단위 갱신은 이걸 오일러 적분으로 근사한 것이라 fps마다 궤적이 달라져요

speed = 10일 때 0.1초 뒤 남은 거리

30fps는 (2/3)³ ≈ 29.6%
60fps는 (5/6)⁶ ≈ 33.5%
120fps는 (11/12)¹² ≈ 35.2%
fps → ∞ 극한은 e⁻¹ ≈ 36.8%예요

저fps일수록 목표에 더 빨리 따라붙어요

---

speed·Δt가 1을 넘으면 망가져요

히치로 Δt가 0.25초로 튀면 speed = 10일 때 α = 2.5가 돼요

UE의 Lerp는 Clamp가 없으니 목표를 지나쳐서
원래 남은 거리의 1.5배만큼 반대편으로 튀어요
α > 2가 이어지면 오차가 매 프레임 커지면서 발산해요

오일러 적분의 안정 조건인 speed·Δt < 2가 깨지는 것과 같은 얘기

---

Pos = FMath::Lerp(Pos, Target, 1.f - FMath::Exp(-Speed * DeltaTime));

매 프레임 남은 거리에 exp(−speed·Δt)가 곱해져요

exp(−speed·Δt₁)·exp(−speed·Δt₂)·… = exp(−speed·(Δt₁ + Δt₂ + …))이라서
프레임을 어떻게 쪼개든 총 경과 시간만으로 결과가 정해져요

α가 1을 넘지 않으니 안전해요

---

x가 작을 때 1 − exp(−x) ≈ x

흔히 쓰는 speed·Δt는 이 정확한 값의 1차 근사이고, 
고fps에서 "대충 맞는" 이유가 이거예요
