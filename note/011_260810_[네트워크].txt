Authority
Authority는 그 오브젝트의 시뮬레이션을 돌리고, 상태를 확정하고, 나머지에게 뿌리는 주체

Server authority

---

Distributed authority

authority가 오브젝트 단위로 쪼개져 클라이언트들에게 분산됩니다

A small, lightweight central state service tracks a minimal amount of game state and routes network traffic
There is no server simulating the game
each connected game instance runs a subdivision of the simulation

---

입력 반응성

---

FragmentationPipelineStage

MTU 단위 패킷 분할

UTP는 기본적으로 MTU(약 1400바이트)에 들어가는 메시지만 보낼 수 있고, 
그보다 큰 페이로드는 여러 UDP datagram으로 쪼개서 보내고 재조립해야 합니다. 

기본 pre-fragmentation 용량은 4096바이트, 
최대 약 20MB(reliable과 조합하면 약 88KB)

"어떤 프로퍼티를 복제할지"는 한 층 위인 netcode 레이어의 일
NGO의 NetworkVariable dirty tracking
Netcode for Entities의 ghost field 직렬화

---

ReliableSequencedPipelineStage

UDP 위에 TCP스러운 보장을 얹습니다
sequence number + ACK + 재전송 + 순서 어긋난 패킷 버퍼링

연결당·파이프라인당 in-flight 32패킷 제한
(최대 2040이지만 문서 권장 상한은 256
재전송 버퍼가 미리 할당되므로 서버 메모리를 먹습니다

ofor very important traffic that you can't afford to lose
(like RPCs and character actions)
아껴 쓰라고 합니다

---

제한이 파이프라인 단위이므로
RPC용과 채팅용 reliable 파이프라인을 따로 만들어 우회하는 트릭도 문서에 나옵니다

---

SimulatorPipelineStage
테스트 도구

로컬에서 인위적으로 나쁜 네트워크 조건을 주입해서, 
localhost나 LAN에서 개발하면서도 
실제 열악한 환경을 확인하게 

packetDelayMs — 좋은 광랜은 20, 나쁜 모바일은 200
packetJitterMs — 보통 delay의 절반 이하
packetDropPercentage — 나쁜 모바일이어도 3을 넘기는 경우는 드묾
maxPacketCount — 동시에 지연시킬 수 있는 패킷 수

ILPostProcessor

Fusion은 루프와 상태 메모리를 빼앗아서 해결했습니다

(a) [Networked] 프로퍼티는 C# 필드가 아닙니다

"add the [Networked] attribute to an auto-property of a NetworkBehaviour derived class, 
which instructs Fusion to automatically generate IL code 
that connects the property's getter and setter 
to the State memory buffer of the associated Network Object."

"Internally Fusion stores the entire networked state for each tick 
as a single memory buffer, called a Snapshot."

tick별 월드 전체 상태가 하나의 연속 메모리 블록입니다
그래서 롤백이 memcpy 한 번입니다

상태가 C# 힙에 흩어져 있으면 불가능한 일

---

(b) FixedUpdateNetwork()가 FixedUpdate()를 대체합니다

"FixedUpdateNetwork() can be called multiple times for the same state transition 
to re-simulate the current predicted state 
based on updates received from the server."

롤백이 사용자에게 투명한 이유

"The re-simulation is transparent for [Networked] properties 
because Fusion will reset the network state before calling FixedUpdateNetwork() for re-simulation purposes."

비멱등 부작용은 IsResimulation / IsForward로 가드
이미 시뮬레이션한 tick인지 처음인지를 구분해서, VFX·사운드·스폰을 재실행에서 건너뜁니다

---

상태가 blittable해야 합니다
INetworkStruct는 "must be blittable, which means it has an absolute memory footprint in both managed and unmanaged contexts"

C# 컬렉션을 못 씁니다. 
NetworkArray, NetworkDictionary, NetworkLinkedList, NetworkString(고정 크기)으로 대체해야 하고, 
전부 [Networked] 프로퍼티로 선언해서 ILWeaver가 backing memory에 연결하게 해야 합니다

게임플레이 로직을 FixedUpdateNetwork 안에 넣어야 합니다
일반적인 MonoBehaviour 코딩 스타일과 결별
