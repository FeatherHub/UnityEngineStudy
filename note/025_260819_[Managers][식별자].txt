instanceID → EntityId

Starting in Unity 6.4, Unity replaces the 32-bit integer InstanceID with the 64-bit EntityId struct

EntityId unifies the way GameObjects and entities identify Unity objects
and removes legacy assumptions about how object identifiers behave

---

legacy assumption들

부호 — 음수면 런타임 생성, 양수면 persistent
지금은 아무 의미 없고 모든 값이 양수

정렬 순서 — instanceID 정렬이 "우연히" 생성 순서를 반영하는 경우가 있었다
EntityId는 순서에 의미가 없다. 파괴된 객체의 값을 재사용하기 때문에

즉 index + generation 조합의 handle로 읽히지만, bit layout은 비공개이고
버전마다 바뀔 수 있다고 명시되어 있다

index + generation

객체를 배열에 담고 index로 가리킨다고 하자
3번 슬롯의 주인이 죽고, 나중에 다른 객체가 3번 슬롯에 들어온다

옛 핸들은 여전히 3을 들고 있다
역참조하면 크래시가 나지 않는다. 조용히 엉뚱한 객체를 돌려준다

해법이 세대 번호

슬롯마다 generation 카운터를 둔다
슬롯을 재사용할 때마다 1 올린다
핸들은 index와 함께 그때의 generation을 복사해 들고 다닌다

역참조할 때 handle.generation == slot.generation을 본다
다르면 "이미 죽었다"

InstanceID → EntityId의 크기 확장이 여기서 설명된다

---

After Unity destroys an object, it can reuse that object's EntityId value for a different object

EntityId ordering is arbitrary
two objects created one after another can have values in any order

the bit layout is an implementation detail
index와 generation에 몇 비트씩 줄지는 언제든 바꿀 수 있다
