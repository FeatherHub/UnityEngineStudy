생성자

리터럴과 순수한 C# 객체
인스펙터에서 넣은 값은 아직 도착하지 않았어요

유니티는 생성이 끝난 뒤에 직렬화된 값을 덮어쓰기 때문
생성자 시점의 [SerializeField] 필드에는 초기화식의 기본값만

Random.Range를 부르면, Awake나 Start에서 부르라는 예외가 나요

---

Awake

자기 자신이 유효해져요

인스펙터 값이 들어와 있고
자기 몸(같은 오브젝트와 자식의 컴포넌트)을 볼 수 있고
엔진 API도 쓸 수 있어요

대신 이웃은 아직 유효하지 않아요

자기 컴포넌트 캐싱, 자기 값에서 파생되는 상태, 레지스트리에 자기를 등록하는 일

---

Initialize

씬에 미리 놓인 오브젝트는 이 단계를 아예 거치지 않아요

비활성 상태로 생성된 오브젝트는 
Awake가 활성화될 때까지 미뤄져요

그러면 Initialize가 Awake보다 먼저 돌 수 있고, 
나중에 Awake가 같은 필드를 덮어쓸 수도 있어요.

---

Start

이웃들의 Awake 결과가 유효해져요

다른 객체의 상태를 읽고, 이벤트를 구독하고, 서로를 잇는 일은 여기서 해요

---

편집 시점의 Reset과 OnValidate

활성화될 때마다 반복되는 OnEnable

---

너무 이르면 아직 유효하지 않은 정보를 읽어요

생성자에서 인스펙터 값을 읽으면 기본값이 나오고
Awake에서 주입값을 읽으면 null이 나와요

---

너무 늦으면 남들이 그걸 필요로 할 때 아직 비어 있어요

자기 값만으로 정해지는 필드를 Start에서 채우면, 
다른 객체의 Start가 먼저 돌 때 빈 값을 보게 돼요

race 쪽은 전자 회로에서 왔어요. 

1950년대 스위칭 회로 연구에서 이 말이 쓰였어요. 
1954년 데이비드 허프먼의 박사 논문에 등장하는 게 잘 알려진 예

두 신호가 서로 다른 경로를 달려 같은 게이트에 닿을 때, 
누가 먼저 도착하느냐에 따라 출력이 달라지는 상황을 경주에 빗댄 거예요

회로 쪽에서는 이걸 race hazard라고도 불렀는데, 
hazard는 주사위 놀이 이름에서 온 말이라는 설이 있어요. 
이름 자체가 "주사위가 결과를 정하는 처지"라는 뜻이에요.

---

누가 먼저 도착하든 최종 상태가 같으면 non-critical race
도착 순서에 따라 최종 상태가 달라지면 critical race

모든 경주가 버그인 건 아니에요
결과가 갈릴 때만 버그예요

---

두 사건 사이에 "무엇이 먼저 일어났다"는 관계가 
시스템 안에서 정해져 있지 않은데, 

결과가 그 둘의 순서에 달려 있다면 그게 race condition이에요. 
순서가 없는데 순서에 기대고 있는 처지인 거죠.

---

public class Difficulty : MonoBehaviour

public class Enemy : MonoBehaviour
{
    [SerializeField] EnemyDeps sceneDeps;     // 씬 배치 인스턴스의 출처 (편집 시점)
    EnemyDeps deps;                           // 클래스 내부가 실제로 쓰는 것 (출처와 무관)

    bool ready;

    // 런타임 생성 인스턴스의 문: 스포너가 Instantiate 직후 부른다
    public void Initialize(EnemyDeps deps)
    {
        this.deps = deps;
        ready = true;
    }

    void Start()
    {
        if (!ready) Initialize(sceneDeps);    // 씬 배치 인스턴스도 같은 문을 통과한다
    }

    void Update()
    {
        // 여기부터는 deps만 믿는다. 이 인스턴스가 어디서 왔는지 묻지 않는다
    }
}

두 경로가 이렇게 합류해요

런타임 생성 인스턴스는 Instantiate 안에서 Awake가 돌고, 
곧바로 스포너가 Initialize를 불러요. 
나중에 Start가 돌 때는 이미 준비돼 있으니 그냥 지나가요. 

씬 배치 인스턴스는 Awake를 거쳐 Start에 오면, 
자기 직렬화 값인 sceneDeps를 들고 같은 Initialize를 통과해요. 

어느 쪽이든 Update 전에는 같은 상태에 도착해요
