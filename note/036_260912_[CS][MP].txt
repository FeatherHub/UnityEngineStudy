---

TLB
Translation Lookaside Buffer

가상 메모리 주소를 실제 물리 메모리 주소로 변환하는 과정을 
빠르게 처리하기 위해 
CPU 내부에 탑재된 고속 하드웨어 "캐시" 메모리

CPU가 프로그램의 가상 주소를 참조해 실제 데이터에 접근하려면 
메모리에 있는 페이지 테이블을 조회해야 합니다

하지만 주소 변환을 위해 매번 메모리에 접근하면 전체적인 실행 속도가 크게 떨어집니다. 
"TLB"는 최근에 변환되었던 가상 주소와 물리 주소의 짝을 기억해두어, 
동일한 페이지를 다시 참조할 때 페이지 테이블을 거치지 않고 곧바로 물리 주소를 찾아낼 수 있게 해줍니다

주소 변환 정보가 "TLB"에 존재하지 않는 상황을 "TLB 미스(Miss)"라고 하며, 
이 경우에는 느린 메인 메모리의 페이지 테이블을 직접 조회한 뒤 
그 정보를 "TLB"에 다시 기록하게 됩니다. 

프로세스가 바뀔 때마다 가상 주소 공간이 달라지므로 
"TLB" 전체를 비우거나 프로세스 식별자(ASID)를 이용해 유효성을 갱신하는 과정이 동반됩니다.

페이지 테이블을 갈아끼울 필요가 없습니다. 주소 공간은 하나고, 통행증만 바뀝니다

"KPTI"는 "Kernel Page Table Isolation"

2018년에 알려진 하드웨어 취약점인 "Meltdown"을 방어하기 위해 도입된 기술

유저 스페이스와 커널 스페이스의 페이지 테이블을 완전히 둘로 나누어 관리

기존에는 프로세스가 유저 모드로 실행될 때도 커널 영역의 주소가 페이지 테이블에 함께 존재했습니다
단지 권한 비트가 유저 모드에서의 접근을 막도록 설정되어 있을 뿐이었습니다

"Meltdown"은 유저 모드 코드가 접근할 수 없는 커널 메모리 주소를 가리키는 코드를 
투기적으로 실행시킨 뒤
권한 검사 에러가 발생하여 실행이 취소되더라도
이미 캐시에 로드된 데이터의 흔적을 부채널 공격 기법으로 읽어내는 방식으로 동작했습니다

프로세서는 명령어 처리 속도를 극대화하기 위해 조건문 결과나 권한 검사 결과가 확정되기도 전에 
다음 명령어를 미리 예측해서 실행합니다.
만약 나중에 예측이 틀렸거나 권한 검사에서 실패한 것으로 판명되면, 
프로세서는 레지스터나 메모리 등 아키텍처 상태를 원래대로 되돌려

     ├─ device             /dev/...

     ├─ epoll instance

     ├─ signalfd
     ├─ timerfd
     ├─ inotify instance
     └─ memfd ...

문자 디바이스 — tty, /dev/null, /dev/urandom. 대개 seek 불가
블록 디바이스 — /dev/sda. seek 가능
소켓 — struct socket이 붙고 자체 상태 기계를 가짐.
파이프 / FIFO — 커널 버퍼(Linux 기본 64KB). 오프셋이 없음, lseek하면 ESPIPE

---

PID — Process ID
실제로는 TGID(Thread Group ID)

커널 내부에서 pid는 스레드 하나를 가리키고, tgid가 프로세스를 가리킵니다

getpid()는 tgid를, gettid()는 pid를

---

PPID — Parent Process ID

부모가 먼저 죽으면 자식은 init(PID 1) 또는 가장 가까운 subreaper에게 재부모화되고 PPID가 바뀝니다

---

PGID — Process Group ID

그룹 리더의 PID를 그대로 씁니다
특정 PID를 그룹 이름으로 재사용

---

셸에서 cat a.txt | grep foo | wc -l을 돌리면 프로세스가 셋 생깁니다. 
Ctrl+C를 누르면 누구에게 시그널을 보내야 하나?

하나에게만 보내면 나머지가 살아남습니다
전부에게 보내면 셸까지 죽습니다

"사용자가 하나의 작업으로 인식하는 프로세스 묶음" 이라는 단위가 필요
그게 프로세스 그룹, 즉 셸의 job

---

kill()에 음수 PID를 넣으면 그룹 전체에 갑니다

kill(-1234, SIGTERM)   /* PGID 1234 그룹 전체 */
killpg(1234, SIGTERM)  /* 같은 것 */
