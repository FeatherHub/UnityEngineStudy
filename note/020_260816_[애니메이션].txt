Animator Controller
.controller 에셋이며 Animator 컴포넌트가 참조합니다

계층은 Layer → StateMachine(중첩 sub-state machine 포함) → State → Motion(AnimationClip 또는 BlendTree)

State 간 연결은 Transition
외부 입력은 Parameter(float / int / bool / trigger)

---

Layer: weight, Avatar Mask, Blending(Override / Additive), Sync, IK Pass. 상체·하체 분리나 표정 추가에 사용
Transition: condition, Has Exit Time, Exit Time, Transition Duration, Interruption Source
StateMachineBehaviour: state에 붙이는 스크립트. OnStateEnter/Update/Exit/Move/IK, OnStateMachineEnter/Exit.
Animator Override Controller: 구조는 유지하고 클립만 교체

---

상태머신 평가(Director.PrepareFrameJob)는 워커 스레드에서 병렬 실행되지만 
OnStateMachineEnter/OnStateMachineExit 리스너가 존재하면 그 평가가 메인 스레드로 제약

transform write는 한 hierarchy당 한 스레드만 접근 가능하므로 Transform.root 기준으로 그룹핑됩니다
같은 hierarchy에 Animator를 여러 개 두면 병렬화 입도가 떨어집니다

.unitypackage

받으면 Assets/ 아래에 압축이 풀립니다
버전 개념이 없습니다. 업데이트는 덮어쓰기고, 내가 고친 부분과 충돌합니다

의존성 해결이 없습니다
두 에셋이 같은 라이브러리의 다른 버전을 들고 오면 수동으로 푸는 수밖에 없습니다.

전부 Assembly-CSharp에 합류해 컴파일 시간에 기여합니다

git에 통째로 커밋됩니다

---

지금의 UPM

패키지 실체는 전역 캐시에 있고 프로젝트에는 참조만 있습니다

Packages/manifest.json(프로젝트 매니페스트)이 의존성 목록이고, 이 파일만 커밋하면 됩니다

semver 기반 버전과 의존성 해결. 
각 패키지는 package.json(패키지 매니페스트)에 name/version/dependencies를 갖습니다.

패키지가 자체 asmdef를 들고 오므로 내 Assembly-CSharp 컴파일에 영향을 주지 않습니다

Unity 레지스트리, scoped registry(npm 호환, OpenUPM이 여기), git URL, 로컬 경로/tarball

---

에디터 안의 Asset Store 창이 없어지고 Package Manager의 My Assets 탭으로 통합됐습니다
현대 오픈소스 Unity 라이브러리는 대부분 Asset Store가 아니라 git URL이나 OpenUPM으로 배포됩니다
