IA32_LSTAR
Long System Target Address Register

유저 공간(Ring 3)에서 SYSCALL 어셈블리 명령어가 실행되었을 때, 
CPU가 제어를 전환하여 커널 공간(Ring 0)으로 점프할 진입점(Entry Point) 가상 메모리 주소를 저장

CPU가 IA32_LSTAR MSR (Model Specific Register)에 설정된 주소를 읽어 Instruction Pointer(RIP)에 로드합니다.

이를 통해 권한이 Ring 0로 승격되며 커널의 시스템 콜 핸들러 코드가 즉시 실행됩니다.

---

페이지 테이블에 커널 페이지가 supervisor 전용으로 표시돼 있어서, 점프하려는 순간 폴트가 납니다

모드 전환을 일으키는 것 말고는 아무 일도 안 하는 특수 명령어
그 명령어는 "어디로 갈지"를 지정하지 않습니다. 커널이 미리 정해둔 곳으로 갈 뿐이에요.

Σ = 약속 목록. 손님이 의지해도 되는 것들의 목록.

메뉴판에 있으면 → 주방이 못 바꿉니다. 바꾸면 계약 위반이에요.
메뉴판에 없으면 → 주방이 마음대로 바꿉니다. 냄비를 바꾸든 요리사를 갈든 손님이 뭐라 할 수 없습니다.

"Σ 경계를 어디에 그을 것인가"는 메뉴판에 뭘 올릴지 정하는 일입니다.

많이 올리면 — 손님은 많은 걸 믿을 수 있지만 주방이 아무것도 못 바꿉니다.
적게 올리면 — 주방은 자유롭지만 손님은 믿을 게 별로 없습니다.

main 은 프로그램의 진입점이 아닙니다. 진짜 진입점은 _start 입니다.
커널이 execve 로 프로그램을 올릴 때 main 을 부르지 않아요

L1/L2/L3 cache는 일반적으로 SRAM
두 inverter가 서로 물려 있어서 전원이 있는 동안 0/1 상태를 계속 유지
DRAM처럼 주기적인 refresh가 필요하지 않다

DRAM보다 빠르지만 bit당 면적과 회로가 복잡

---

Register
→ transistor들을 latch/flip-flop으로 연결

SRAM
→ transistor들을 SRAM cell로 연결

DRAM
→ transistor + capacitor cell

---

레지스터 — 플립플롭 또는 다포트 SRAM. 비트당 트랜지스터 10~20개
캐시 — SRAM. 비트당 트랜지스터 6개
메인 메모리 — DRAM. 비트당 트랜지스터 1개 + 커패시터 1개

---

SRAM 셀 — 그냥 논리 회로

6개 트랜지스터 중 4개가 인버터 두 개를 서로 물려놓은 것
A 의 출력이 B 의 입력이고 B 의 출력이 A 의 입력
이러면 두 상태 중 하나로 고정됩니다. 래치

---

DRAM 셀

읽으면 파괴됩니다. 커패시터의 전하를 비트라인과 나눠 갖는 방식이라 읽고 나면 원래 값이 사라집니다
감지 증폭기가 복원해서 다시 써넣어야
