Instantiate / SetActive 경로

---

Awake가 초기화 인자를 보게 하는 패턴

var go = Instantiate(prefab);              // prefab 자체가 inactive 상태
go.GetComponent<Enemy>().Setup(config);    // Awake 아직 미호출
go.SetActive(true);                        // 여기서 Awake → OnEnable

이 패턴의 전제가 inactive prefab

---

Awake는 인스턴스당 1회.
컴포넌트 enabled = false여도 GameObject가 active면 호출됩니다
Unity calls Awake regardless of the value of Behaviour.enabled

GameObject가 inactive면 활성화될 때까지 지연되고
그 전에 파괴되면 Awake도 OnDestroy도 호출되지 않습니다.

Awake 에서 예외가 나면 Unity 가 그 컴포넌트를 비활성화한다
If a script component's Awake throws an exception, Unity disables the component

Awake는 자기 자신을 세우는 자리, Start는 남에게 말을 거는 자리
GetComponent로 참조를 잡고 필드를 초기화하는 건 Awake, 
다른 오브젝트의 초기화 결과를 읽는 건 Start.

EndPlay는 이유를 인자로 받습니다
Destroyed, LevelTransition, EndPlayInEditor, RemovedFromWorld, Quit

종료 시에만 저장하고 씬 전환 때는 안 하고 싶다면 OnApplicationQuit에서 별도 플래그를 세워두는 식으로 우회

OnDestroy는 Awake가 불린 적이 있어야 불립니다. 
비활성으로 만들어져 한 번도 켜지지 않은 채 파괴되면 
Awake도 OnDisable도 OnDestroy도 아무것도 오지 않습니다

라이프사이클 메시지

엔진에는 알려진 메시지 목록이 하드코딩되어 있고
각각이 MessageIdentifier로 표현됩니다

어떤 스크립트 클래스가 처음 로드될 때 리플렉션으로 그 클래스와 조상들을 훑어서
"이 클래스가 구현한 메시지는 무엇무엇이다"라는 표를 만들어 
MonoScriptCache에 담아둡니다

표의 각 칸에 들어가는 게 ScriptingMethodPtr, 즉 실제 메서드 포인터입니다

---

리플렉션은 타입당 한 번이고, 그 뒤로는 캐시된 포인터를 곧장 호출합니다
Mono라면 mono_runtime_invoke, IL2CPP라면 생성된 함수 포인터입니다

리플렉션으로 찾으니 접근 제한자를 안 봅니다 — private이어도 걸립니다
이름으로 찾으니 오타는 그냥 "구현 안 함"으로 해석
표의 칸이 하나뿐이니 base와 derived가 같은 이름을 선언하면 하나만 남고

각 컴포넌트 타입에서 그 이름의 메서드를 찾아 호출합니다

BroadcastMessage는 자식 전체로, 
SendMessageUpwards는 부모 사슬로 같은 일을 반복

---

Il2CppObject* Runtime::Invoke(const MethodInfo *method, void *obj,
                              void **params, Il2CppException **exc)
{
    // we wrap invoker call in try/catch here, rather than emitting a try/catch
    // in every invoke call as that blows up the code size.
    try { return InvokeWithThrow(method, obj, params); }
    catch (Il2CppExceptionWrapper& ex) { if (exc) ...store(exc, ex.ex); return NULL; }
}

두 백엔드 모두 캐시된 포인터를 부르는 구조고, 상수 배 차이지 자릿수 차이가 아닙니다
